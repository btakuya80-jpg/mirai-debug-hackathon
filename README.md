# 未来デバッグ（Mirai Debug）

**応募する前に、その会社で働く自分の未来を試運転する。**

Built with Claude: Japan 2026 の提出作品です。

## だれの、どんな課題を、どう解決するか

- **だれの**：これから仕事を選ぶ求職者（とくに未経験の職種に応募する人）。
- **どんな課題**：入社してみないと、合うか分からない。「入ってみたら、思っていたのと違った」で早く辞めてしまう。
- **どう解決するか**：求人1件から、その会社で身につく専門知識を出典つきで読み取り、入社1週間〜3年後までの仕事の場面を絵で試走する。分かれ道で「残る・同じ業界へ・違う業界へ・独立・学び直し・海外」を選ぶと、身につけた知識がどの道で活きるかが分かる。最後に、応募するかを決める材料（身につくこと・気をつけたい所・面接で聞く質問）を持ち帰る。
- 未来を当てる道具ではありません。**次に確かめることを見つける道具**です。

## いまの流れ（2026-11-08）

1. 求人を選ぶ（見本の架空求人5件、または求人の本文を貼る）
2. 会社のまとめ：身につく専門知識を出典つきで出す。求人に書いていないことは補わずに「不明」と出す
3. 自分を設定：年齢と働き方の希望だけ
4. 1本道の試走：入社1週間 → … → 選んだ年数（1年・3年・5年）まで、仕事 → 壁 → 学び → スキルアップ → その後 の5段で場面を見せる
   - 人生の出来事（出会い・結婚する／しない など）を場面の絵の上で選ぶと、1〜2場面で仕事・働き方・給料への影響を見せてから元の流れに戻る
   - 分かれ道も場面の絵の上で6本から選ぶ。選んだ道の場面2つ（職場の絵・新しい職場の人・セリフが道に合わせて変わる）
5. 結局どう成長した？（入社時 → 分かれ道 → 道の先）
6. 持ち帰り：「この会社で3年働くと、あなたは〇〇ができるようになる」の1行と「できる」カード、1年・3年・5年の比べ、面接で確かめる質問。メモは「面接に持っていくメモとして保存」できる

公開ページ（Artifact）：https://claude.ai/artifact/K6R6pgL3hXhuYGpPqUJzyj

## 開発の記録（11/6〜11/7 の状態）

### 2026-11-06・G案に一本化

- 作り込みは **G案だけ** で進めます（`/g`、単体ページは `node scripts/build-standalone.mjs --g` → `dist-g/index.html`）。A〜J案のコードと入口ページは消さずに残しています。
- 画面の頭と結果の画面に「これは試走したシナリオの一つで、未来を約束するものではありません」を必ず出します。
- 出さない物：実名・実在の会社名／点数・％・合否／API キー／保険・借入などのお金の提案／広告枠。登場する会社・人物はすべて架空です。

### Claude のつなぎ方（API キーを持たない）

- 公開した Artifact の **`sample` 機能** で Claude を呼びます（`window.claude.use("sample")` → `sample.json(prompt)`）。見る人の Claude のアカウントで動き、最初の1回だけ見る人に許可を聞きます。コードにもサーバーにもキーはありません。Vercel も使いません。
- 呼ぶのは **1回だけ**。求人の本文を渡し、決まった形の JSON（会社まとめ・身につく専門知識・6本の道の判定・入社1年の場面・分かれ道の様子・道ごとの場面・次に確かめること）を返させます。形は `src/lib/ai.ts` の `buildPrompt` に書いてあります。
- ページからは外のサイトを読めないため、**見本の求人URL**は用意した架空の求人本文を、**それ以外のURL**は求人の本文を貼ってもらって Claude に渡します。
- 読めない項目は埋めずに「不明」と出します。求人に無い想定（AIスキルなど）は「仮定」と出します。
- Claude を使えない時（Artifact の外・許可されない・混雑・形が崩れた JSON）は、**見本データで続け**、会社まとめの画面に理由を出します。
- 返ってきた JSON は `registerAiRead` で確かめてから画面のデータにします（Lv は 0〜4 に丸め、場面ごとに1つずつ上がるようにそろえる）。

### 職種ごとに見せ方を差し替える考え方

- 職場の種類（`place`：工場・オフィス・建設現場・物流・飲食）ごとに、背景の絵・場面の言葉・人物の役職を切り替えます。新しい職種は「背景の絵1枚＋場面の言葉」を足せば増やせます。
- Claude が読んだ求人は、いちばん近い職場の種類を選ばせ、その見本の求人をひな形にして中身（会社まとめ・知識・場面）だけを差し替えます（`registerAiRead`）。

### 11/6 夕の直し（使った人の感想から）

| 項目 | 中身 |
|---|---|
| スキルと道 | 場面が終わるごとに「この場面で手に入れたスキル」を出し、6本の道へ線でつなぐ（太い線＝活きる、点線＝少し活きる） |
| 自動で次へ | 「ゆっくり」「ふつう」の時は、場面が終わると数秒後に次の場面へ自動で進む（あと何秒かを表示。「止める」で自分で進めるに切り替え）。移る時は「次の場面へ　時間が進みます」の演出 |
| 分かれ道 | 分かれ道に入ったら、画面の枠を光らせ「ここで、道を選んでください」を大きく出す。自動で進めていても、ここでは止まって待つ |
| セリフ | 命令口調や意味の分かりにくい言い方を、自然な話し言葉に直した（例：「次の班長、考えておけ」→「次の班長を任せたいと思っている。考えてみてくれる？」） |
| 気持ち | 場面に出てきた人全員（上司・先輩・同期・家族・現地の仲間・教え子・パートナー）の気持ちを、表情＋一言＋ゲージの絵で出す |
| 人生の出来事のマス | 年表の年齢の順に、出会い・交際・結婚・家族のマスを仕事の場面の間へ入れる（すごろくのマス）。押すと選ぶ所へ移る |
| 「残る」と比べる | 残る以外の道を選んだら、「もし残っていたら」と並べて見せ、「未来を当てるのではなく、次に確かめることを見つける」で締める |
| 将来の導線 | 最初の画面に、求人サイトに置く「未来を試走する」ボタンのイメージを1枚だけ出す（動かない見本） |

### 持ち帰り画面（システムのゴール・11/7）

試走の最後に、使った人が「応募するかを自分で決められる材料」を1枚で持ち帰れます。

| 欄 | 中身 |
|---|---|
| ① 身につく専門スキル | AIスキルも含め、分かれ道の時点での Lv（知った・できる・任される・教えられる）。求人の本文の引用、または「仮定」 |
| ② 開ける道 | 6本の道を、活きるスキルの多さで太い・ふつう・細いの線で描く（数字は出さない） |

| ④ 面接で確かめる質問 | Claude が挙げた質問と、会社まとめで「不明」だった所を質問の形にしたもの |
| ⑤ 次の一歩 | 応募する／他の求人と比べる／1年・5年でも見てみる。メモはテキストで保存・印刷できる |

## 画面の流れ（全案共通・求職者側）

1. 求人ページ（架空）→「入社後を試運転する」
2. 入力：選ぶだけの10問＋住むエリア
3. 会社を選ぶ：架空の2社（仮想 あおば社／仮想 みどり物流）
4. 試走中：5本の試走と、時点ごとの進み具合
5. 結果：時点ごとの出来事と分身の動き／能力表（8項目・S〜G）と理由／辞めたくなる度合い（高・中・低）と理由／分かれ道（1本は違う業界へ移る筋）／上司あり・なしの比べ表示／面接で確かめる質問
6. 2社に入った場合の比べ表示

各段階は URL の `#job` `#input` `#company` `#run` `#result` `#compare` で直接開けます（例：`/b#result`）。
デモ動画を撮る時は `?demo` を付けると、右下の説明窓（ⓘ）が出ません（例：`/a?demo#run`）。

## 守っていること

- 企業に合否・点数・％を出さない。「予測」ではなく「シナリオ（筋書き）」として見せる。
- 辞めたくなる度合いは「高・中・低」の3段階だけ。
- 能力表は人の格付けではなく、本人が選んだ目標にどこまで近づいたかとして出す。
- 実在の人名・会社名は使わない（すべて架空）。他社のゲーム作品名・キャラクターも使わない。
- 企業側の入力画面は今回は作らない（会社データは JSON で用意）。
